## What changed since the reports

- **AC-1 / DV-1 is fixed** by [#359](https://github.com/jclind/prepify/pull/359), live in 1.2.1.
  `deleteRecipeImage` only deletes `recipeImages/{ownerUid}/{file}` (`server/util/firebaseStorage.js`).
  It still takes the bucket from the URL, and the migration script
  `server/scripts/migrateRecipeImagesToUid.js:246` deletes flat sources without that check. Both are in 1b.
- **The quota dispute.** CR rejected "paid quota counts requests before validation". AC rated it High.
  AC is right about the global counter: `server/util/paidQuota.js:60` increments the shared daily pool
  before the handler validates the body, so malformed requests from throwaway accounts use up everyone's
  capacity without a paid call. CR is right that counting valid attempts conservatively is correct. 1e
  moves the reservation after validation and keeps counting valid attempts.
- **The quota is not a hard ceiling today.** When the counter errors, `paidQuota.js:113` logs and calls
  `next()`. Decision D3 asks whether that should change.

## Ground rules for every PR

1. One PR per item below unless it says otherwise. Under about 300 changed lines.
2. Each code PR includes a test that fails on `development` before the fix. The PR body says how that
   was shown (run the new test against the old code, as #359 did).
3. Server or security PRs get a `/codex-review` before merge.
4. Land through `/worktree-land`. Promote in groups: after Phase 1 as one release, then as convenient.
5. When a PR closes an item, tick it in `docs/BACKLOG.md` or the audit doc it came from (Phase 5 covers
   the rest).
